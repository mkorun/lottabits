# ADR 0003: Printables as self-contained HTML with embedded fonts, PDFs from headless Chrome

Status: accepted, 2026-10-04.

## Context
Printables are a primary interface (SPEC.md section 9). A misread character on a password map or a misread word number in a
booklet produces a wrong secret, so legibility is a security property. System fonts differ between machines: `0`/`O` and
`1`/`l`/`I` look alike in many of them, and the same HTML would print differently on every computer.

## Decision
- Printables are HTML generated by `cmd/printables` from Go templates and the same data packages as the CLI.
- Two fonts are embedded in every file as base64 data URLs, so the files need nothing but a browser:
  *Atkinson Hyperlegible Next* for text and *Atkinson Hyperlegible Mono* for numbers, words and characters. Both come from the
  Atkinson Hyperlegible family, made for distinguishing similar characters (slashed zero, distinct `1`/`l`/`I`), are licensed under the
  SIL Open Font License 1.1 and are stored unchanged in `printables/fonts/` with their license and provenance.
- PDFs are rendered with headless Chrome or Chromium (`tools/render_pdfs.py`) in the release job and for test prints.
  The tool checks every page count against the manifest. HTML stays canonical, because PDFs carry creation dates.

## Alternatives
- System font stacks: no new files, but output differs per machine and confusable glyphs are not under control.
- A Go PDF library: a dependency against ADR 0001 and more code to audit than one call to an existing browser.
- Fonts as separate files next to the HTML: smaller output, but a single file copied on its own would silently fall back
  to system fonts.

## Consequences
Each HTML file is about 230 KB larger (8.6 MB for all printables in both languages). Font files are third-party data with an
OFL notice that must ship with the source.
